# LangChain RAG Chatbot

A production-ready **Retrieval-Augmented Generation (RAG) chatbot** that answers questions grounded in the official **LangChain documentation**. It combines **LangChain (LCEL)**, **NVIDIA NIM** models, a persistent **ChromaDB** vector store, a **SQLite** metadata database, and a **Gradio** multi-turn chat UI — with a full **RAGAS** evaluation suite covering all six quality metrics.

## Overview

The system runs an end-to-end RAG pipeline:

1. **Ingest** — pulls the official LangChain Python OSS docs corpus (`llms-full.txt`, ~7 MB, 538 pages), splits it into overlapping chunks (1000/200), embeds them with NVIDIA NIM, and stores them in a persistent ChromaDB collection while tracking metadata in SQLite.
2. **Retrieve** — loads the vector store and uses **MMR retrieval** (`fetch_k=20`, `lambda_mult=0.7`, `top_k=8`) to select diverse, relevant chunks for a question. A widened similarity pool with an MMR diversity back-fill keeps context relevant without narrowing to a single page.
3. **Generate** — a grounded NVIDIA NIM LLM answers **strictly from the retrieved context**, with per-sentence `[Source: …]` citations, an on-topic guard, and an explicit refusal when the context cannot support an answer.
4. **Chat** — the Gradio UI maintains multi-turn conversation history and renders expandable source documents under every answer.
5. **Evaluate** — a curated 35-question dataset is scored with RAGAS across six metrics; a markdown report is generated with per-metric scores vs targets and latency/system statistics.

## Features

- **Grounded, citable answers** — the LLM is constrained to answer only from the retrieved context, with inline `[Source: …]` citations per sentence.
- **LLM-free retrieval refinement** — query questions are tuned to the corpus; the widened similarity pool + MMR fallback fixes the weak-narrow-band behavior of small embedding models.
- **Multi-turn conversation** — per-session chat history with persistent message stores.
- **Expandable sources** — every answer shows its retrieved source documents in the UI.
- **Idempotent ingestion** — content-hash gating skips unchanged re-runs safely; metadata tracked in SQLite.
- **Full RAGAS evaluation** — context precision, context recall, context relevancy, answer relevancy, faithfulness, and answer correctness, plus latency and token tracking.
- **Graceful error handling** — missing API key, empty store, off-topic questions, and pipeline failures surface cleanly.

## Setup

### Prerequisites

- [uv](https://docs.astral.sh/uv/) (manages the Python 3.12 environment)
- An [NVIDIA API key](https://build.nvidia.com/) with access to the NIM embedding & chat endpoints

### 1. Install dependencies

```bash
uv sync
```

### 2. Configure environment

```bash
cp .env.example .env
```

Then set your NVIDIA key in `.env`:

```
NVIDIA_API_KEY=nvapi-...
```

Recommended settings (already the defaults — also in `.env.example`): `SEARCH_TYPE=mmr`, `FETCH_K=20`, `LAMBDA_MULT=0.7`, `TOP_K=8`, `CHUNK_SIZE=1000`, `CHUNK_OVERLAP=200`.

### 3. Run ingestion

Loads the LangChain docs into the vector store (first run downloads the corpus and embeds ~5k chunks):

```bash
uv run python -m src.ingest
```

Preview without spending API credits:

```bash
uv run python -m src.ingest --dry-run
```

> Ingestion is idempotent: if the corpus and store are unchanged, re-running is a no-op.

### 4. Run the Gradio app

```bash
uv run python src/app.py
```

Open the printed URL (default `http://127.0.0.1:7860`).

### 5. Run evaluation

Requires the API key and an ingested vector store.

```bash
uv run python -m src.evaluate               # full dataset (35 questions)
uv run python -m src.evaluate --limit 5     # quick subset
uv run python -m src.evaluate --fresh       # ignore the progress cache
```

A detailed `reports/evaluation_report.md` is generated and a summary table is printed. Per-question runs are cached in `evaluation/results_cache.json` so interrupted runs can resume.

## Notes

- **RAGAS compatibility**: Ragas 0.4.3 imports a Vertex AI chat model that was removed from recent `langchain-community`. `src/_ragas_shim.py` registers a harmless stub so Ragas loads while the rest of the stack stays on modern versions.
- **Context relevancy**: removed from Ragas ≥ 0.4.0, so `src/evaluate.py` reimplements the classic Ragas algorithm as a custom metric (LLM-judged fraction of relevant retrieved sentences).
- **Embedding model**: `nvidia/nemotron-3-embed-1b` is the supported model (the older `nvidia/nv-embedqa-e5-v5` returns 410 Gone). If you switch embedding models you must clear `chroma_db/` and re-ingest — embeddings must stay consistent across ingest and retrieval.
- **Evaluation costs**: the full RAGAS run performs ~210 judge sub-tasks; use `--limit 5` for a quick sanity check.
